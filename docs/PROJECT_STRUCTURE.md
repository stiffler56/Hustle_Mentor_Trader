# Project Structure

This project is mainly a frontend React/Vite app with a small Supabase backend layer.

## Main Folders

| Path | Part | Purpose |
| --- | --- | --- |
| `src/` | Frontend | React app source code. This is where the browser UI lives. |
| `src/main.tsx` | Frontend entry | Starts the React app and renders `src/app/App.tsx`. |
| `src/app/` | Frontend app | Main application code: pages, components, hooks, services, data, and utilities. |
| `src/app/pages/` | Frontend pages | Full screens/routes such as Dashboard, Journal, Analytics, Auth, AI Mentor, etc. |
| `src/app/components/` | Frontend components | Reusable UI pieces used by pages. |
| `src/app/components/ui/` | Frontend UI library | Shared shadcn/Radix-style base components such as buttons, cards, dialogs, tabs, and inputs. |
| `src/app/data/` | Frontend state/data models | React contexts, mock data, trade types, and local app data helpers. |
| `src/app/hooks/` | Frontend hooks | Custom React hooks. |
| `src/app/services/` | Frontend services | Frontend service wrappers, for example broker-related logic. |
| `src/app/utils/` | Frontend utilities | App calculations and helper functions such as scoring, analytics, pattern recognition, and mentor analysis. |
| `src/styles/` | Frontend styling | Global CSS used by the app. |
| `src/imports/` | Imported assets/content | Figma/imported images and pasted reference text. Usually not core app logic. |
| `supabase/functions/` | Backend | Supabase Edge Functions. This is server-side code deployed/run by Supabase. |
| `supabase/functions/server/` | Backend API | Hono server routes for auth helpers, trades, AI mentor, and key-value storage. |
| `utils/supabase/` | Shared config | Supabase project ID and public anon key generated by the platform. Used by the app to connect to Supabase. |
| `guidelines/` | Documentation/reference | Project guidelines or notes. |
| `dist/` | Build output | Generated production build from Vite. Do not edit directly. |
| `node_modules/` | Dependencies | Installed packages. Do not edit directly. |
| `.vscode/` | Editor config | VS Code workspace settings. |

## Root Files

| File | Purpose |
| --- | --- |
| `package.json` | Project scripts and dependencies. Use `npm run dev` for development and `npm run build` for production build. |
| `vite.config.ts` | Vite build/dev-server configuration and aliases. |
| `index.html` | HTML entry file used by Vite. |
| `postcss.config.mjs` | CSS processing config. |
| `default_shadcn_theme.css` | Default shadcn theme styles. |
| `README.md` | Basic project instructions. |

## Simple Mental Model

- Frontend: `src/`
- Backend/server functions: `supabase/functions/`
- Supabase connection config: `utils/supabase/`
- Generated output: `dist/`
- Installed dependencies: `node_modules/`

## Possible Future Organization

If you want a clearer split later, the project can be reorganized like this:

```text
frontend/
  src/
  index.html
  vite.config.ts

backend/
  supabase/

docs/
```

That move is possible, but it requires updating Vite config, package scripts, import paths, and possibly Supabase deployment paths. For now, the current layout is valid and safer to keep.
